# 把工作规矩改成自己的

原则可以共同使用，管理偏好可以不同。安装前一次选择连接方式、汇报强度与语气；作者默认`auto/full/direct/30`，日常轻量可选`milestones`。安装后在项目`AGENTS.md`的“本项目选择”修改，普通更新保留这些值。

## 少说不，多给判断和办法

第4条负责主动推荐与承担选择，第8条负责自然直白地交代结果。默认目标是把防御、免责式表达较原风格减少约80%，优先写判断、方案、行动和结果；真实限制交代影响与可行下一步。准确的风险和证据缺口照实说。语气可选直接或中性，实际效果用一次熟悉任务来判断。

“更有人性”落实为有判断、有体谅、肯担事：理解人的目的与处境，主动查清能查的条件，少让用户管理Agent和返工。

## 调整规则的入口

| 修改 | 真正控制行为的文件 | 说明 |
| --- | --- | --- |
| 本次临时偏好 | 当前用户指令 | 例如“这次只给结果，不附八条” |
| 项目长期覆盖 | 项目 `AGENTS.md` | 明确写出与默认不同的频率或验收方式 |
| 复用技能默认 | 安装目录 `SKILL.md` | 影响以后加载此技能的任务；更新前保留自己的改动 |
| 范例与解释 | `references/reporting.md` 等 | 仅改范例未必覆盖主指令，须同步行为要求 |
| 列表外观与提示 | `agents/openai.yaml` | 不等于更改工作规则，也不增加宿主工具 |

## 三种合理选择

**作者默认**：工作报告有正常正文与完整八条附录，纯问答免附录。适合希望逐项审查选择和缺口的人。

**阶段报告更轻**：进度消息只报发现、阻塞和下一步；阶段结束与最终交付再附八条。可在项目写：

```text
本项目覆盖 eight-honors 的附录频率：日常进度不附八条，阶段结束与最终交付附完整八条。
保留事实、复用、判断、验收、额度交接等要求；缺口仍须主动说明。
```

**简洁正文**（`concise`）：保留八条对做事的要求，默认用正文报告，用户要复盘时再展开八条。纯问答本来就无需附录，小任务保持直接完成。

## 额度、时间与权限

- 先选实际服务：API/中转用`api`，按服务商真实预算与小阶段交接；ChatGPT计划确认来源后默认五小时剩余30%收尾。所选`quota_mode`和阈值同时传给checker与admit。
- 周 30% 是提示，不要把它误改为五小时足够也停工。周耗尽仍须收尾。
- 调度属于宿主；这里没有 `auto_resume=true` 开关。已配置、已触发、已执行、已验收要分别验证。
- 用户修改开始时间，应停旧触发器，再同步真实配置、检查点和接续提示；不能拿旧方案扩张新授权。
- 给 Agent 判断空间不等于扩大权限。发布、删文件、付费和安装新依赖仍遵守当前授权。

## 怎样知道调整生效

启动新会话，要求它说明读取了哪些规则，并做一次范围清楚的小任务。观察它是否理解目的、复用了现有实现、运行了相关检查、如实陈述缺口，并按你选择的格式交付。仅复述八条不证明行为改变。

修改前保留最好的完整版本，检查 Git diff；只纠正出现具体问题的规则。过多重复、冲突和无条件加载的说明会增加阅读负担，不保证效果更好。
