## 正文草稿

前阵子小火过的 AI 编程八荣八耻，大家可能都见过。

我自己和 Agent 做研究、写代码、改文档、跑长任务时，也慢慢攒出了一套八条。最近整理成了一个最适合 Codex 用户的 skill，叫「新八荣八耻.skill」。模型在进化，工作作风也得跟上。

我最在意几件事：

- 先搞懂我到底要什么，不要把随口的例子当硬要求。
- 先看看成熟方案；真要自己写，讲清为什么。
- 给它已经授权的判断空间，别把每个细节又推回给我。
- 测试过、导出过，和东西实际好用，要分开说。
- 干了什么、为什么这么做、还有哪里没验证，主动交代。
- 快到额度时，提前保存成果和下一步，把收尾报告给出来。

我还保留了一个比较个人化的习惯：正常汇报之后，让它按八条说明本次具体体现。没涉及、没验证都可以直说，别为了格式凑“全部做到”。不喜欢这么长，也能自己改成只在阶段结束出现。

仓库里有 skill、可以合并进 AGENTS.md 的规则片段、报告范例，以及 Codex 只读额度查询和交接脚本。顺便纠正一个小细节：Codex 默认读的是 AGENTS.md，有 S。

提前收尾有工具配合，自动继续还得看宿主有没有真正的调度能力。它不会因为装了一个 skill 就在关机后自动开工；没有机制时必须说清“未启用”。

这是我偏好的工作方式，适合拿去改成你自己的那版。不是首创概念，也没有“效率暴涨几倍”的数据。

## 不宜写成的宣传

不要写“全球首创”“装上永不翻车”“自动无限续命”“模型能力提升 N%”或“所有 Agent 通用实测”。已有同概念项目，额度脚本没有强制拦截器，自动恢复依赖宿主，跨模型也尚无对照评测。
