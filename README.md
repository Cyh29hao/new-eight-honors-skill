## 先看，它会怎样工作

> **你**：修一下营业额导出，只统计已完成订单。我猜是 float 精度，换一种数值类型应该就好了吧？
>
> **Agent**：已复现：取消订单也被计入，多算了 100。只换数值类型仍会算错。我复用了项目已有的统计函数，导出已从 **120.00 修为 20.00**；5 组检查通过。

这是一次独立 Agent 在合成订单上的[真实试用节选](docs/experiments/2026-10-29-forward-test.md)。它核对你的判断，找现成实现，再用实际结果交付。

## 这是什么

**一套管理 Agent 的工作约定，打包成了 skill，也能直接写进 `AGENTS.md`。**

AI 编程“八荣八耻”以前就火过。这是我在长期协作里重新整理的一版：从写代码，扩展到研究、文档、创作和长任务，管的是 **如何理解任务、自己做判断、验收成果，以及向人交代工作**。

## 解决哪些问题

我希望少遇到这些事：方向做偏了才发现；明明有现成方案还从头写；导出成功就说东西好用；过程一直黑箱；额度耗尽以后只剩半截任务。

所以，我把自己的偏好写成八条：**给 Agent 判断空间，也要求它把依据、成果和交接讲清楚。**

## 八条做事标准

> **01　以误认目标为耻，以明确成效为荣。**
>
> **02　以无据断言为耻，以查证求实为荣。**
>
> **03　以闭门造轮为耻，以择优复用为荣。**
>
> **04　以照单全收为耻，以独立判断为荣。**
>
> **05　以表面达标为耻，以实物验收为荣。**
>
> **06　以无声中断为耻，以有据续作为荣。**
>
> **07　以无效消耗为耻，以及时收敛为荣。**
>
> **08　以黑箱推进为耻，以主动汇报为荣。**

八条各管一件事：**目标、证据、复用、判断、验收、接续、成本、沟通。** 小任务直接做，复杂任务才增加必要的计划与检查。[展开执行规则 →](SKILL.md)

## 用起来，有哪些变化

**做事时，会判断。** 分清你的目标和随手举的办法；能复用就复用，建议不合适就拿依据说明。授权内的普通选择由它承担。

**交付时，有交代。** 先说成果、验证和缺口，末尾再按八条说明本次具体怎么做。你能审查它的选择，也能看见哪里还没验。

1. **以误认目标为耻，以明确成效为荣**：以“只统计已完成订单”为目标，把“换数值类型”作为待检查的建议。

3. **以闭门造轮为耻，以择优复用为荣**：采用项目已有的 `completed_total()`，没有另写统计工具或安装依赖。
4. **以照单全收为耻，以独立判断为荣**：依据复现结果修正方法，直接完成已授权的修改。
5. **以表面达标为耻，以实物验收为荣**：运行实际导出入口，读取结果文件，核对五组完整输出。
6. **以无声中断为耻，以有据续作为荣**：保留原始示例，留下修改、验证方法与未验证范围。
7. **以无效消耗为耻，以及时收敛为荣**：相关检查通过后收工，没有扩大成无关重构。
8. **以黑箱推进为耻，以主动汇报为荣**：交代原因、采用的方法、结果和限制。

**长任务中，提前收尾。** 在可查询额度的 Codex 环境中，定期读实时余额；接近预留线时先保存成果、做必要检查，把交接报告交给你。你会看到：

> **额度收尾 · 体验示意**
>
> 已完成：当前可看的成果与验证结果。<br>
> 还没完成：具体缺口和阻塞。<br>
> 下一步：从哪个目录、哪条命令接着做。<br>
> 恢复安排：是否真的启用了自动接续。

**为什么默认预留 30%？** 我使用 Plus 时，往往还要看结果、反馈，再让 Agent 改几轮。如果到最后一点额度才收尾，容易留下半成品，下一轮又要重新解释。30% 是我给**人工验收、后续对话和修改**留的余地，希望大多数多轮任务能更顺畅地收住；这是个人取舍，可以改成 20%、10% 或你自己的数值。

自动继续依赖宿主的实际调度能力；随包提供的是只读额度查询与交接工具。[调整阈值和接续方式 →](references/quota-and-recovery.md)

## 它会怎么改我的 AGENTS.md

合并一个独立的标记块，保留你原来的规则。这个块会约定三件事：

- **怎样做事**：八条原则，以及什么时候自主决定、什么时候查证与验收。
- **怎样汇报**：正常正文在前，八条具体说明在后；进度主动说，缺口如实说。
- **怎样收尾**：长任务留检查点、查额度、交付交接报告；阈值可调整。

```markdown
<!-- EIGHT-HONORS:START -->
## 八荣八耻工作约定
……八条全文、工作报告格式、额度与交接约定……
<!-- EIGHT-HONORS:END -->
```

上方展示结构，[这里是实际写入的完整内容](references/AGENTS.fragment.md)。安装时先备份；已有同一标记块就合并更新，不重复追加。项目默认写入根目录 `AGENTS.md`；全局使用可另选 `~/.codex/AGENTS.md`（设置了 `CODEX_HOME` 时以它为准）。

**Skill 保存方法、示例和工具；`AGENTS.md` 让你的偏好随项目带入新会话。** Codex 的默认文件名是 `AGENTS.md`，有 S。[安装范围与覆盖规则 →](docs/installation.md)

## 发一条消息，开始

**把下面整段发给能操作本机文件的 Codex。** 它会按你的这条指令安装，并合并项目规则；你不需要自己逐份编辑文件。

```text
帮我安装并启用 https://github.com/Cyh29hao/eight-honors-skill 。
在当前项目使用：先读 SKILL.md，把 skill 放到 .agents/skills/eight-honors，
备份已有 AGENTS.md，再合并 references/AGENTS.fragment.md 的标记块；
保留其他规则，已有同一块就更新，遇到冲突先说明具体差异。
完成后告诉我实际改了哪些文件、怎样确认生效。
之后按八荣八耻工作，正常报告后附八条体现。
```

**想先试用、不改长期规则？** 在项目目录运行：

```sh
git clone https://github.com/Cyh29hao/eight-honors-skill .agents/skills/eight-honors
```

再调用 `$eight-honors`。Claude Code 的 skill 目录是 `.claude/skills/eight-honors`，调用 `/eight-honors`，长期偏好合并到 `CLAUDE.md`。[完整安装指南 →](docs/installation.md)

## 谁适合用，哪里能调整

适合能**读写文件、调用工具、遵循较长指令**的 Agent。Codex 是本仓库的主要示例；代码、研究、写作和文档任务都可以采用这套约定。

在 Codex 中，可用 GPT-6.1 Sol 做常规长任务，较难的判断考虑 Astra，写作与视觉工作可考虑 Terra；范围清楚的小任务也可先试 Luna。这是按[官方定位](https://learn.chatgpt.com/docs/models)给的选型方向，实际效果要看你的任务与工具。其他模型也能借用八条，额度适配器则针对 Codex。

- 改做事标准：编辑 [SKILL.md](SKILL.md) 或项目 `AGENTS.md`。
- 改报告详略：在项目里写“只在阶段结束附八条”或自己的要求。
- 改收尾余量：告诉 Agent 新阈值，例如“本项目改成 10%”，查询时使用对应参数。
